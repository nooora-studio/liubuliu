# 验收清单

提案阶段不勾选任何工程验收项。批准并实施后，逐项记录实际验证结果；缺少微信账号、设备或运营处理条件的项目保留未完成，不能用浏览器预览替代。

## 发布与上下文

- [ ] R1：新帖只有一个主体衣服的纠结，照片 1–9 张；无图、超限图或无效文件被明确阻止，不能回退为示意图成功发布。
- [ ] R1：具体纠结 4–400 字、期待效果最多 120 字、品牌最多 30 字，服务端与客户端规则一致；不要求再填重复标题。
- [ ] R1/R2：价格支持 0、正常两位小数及上限，负数、超限和超过两位小数被拒绝；品牌/价格/目标可空，展示不出现无意义占位。
- [ ] R1：封面调整、删除和预览正确；全部照片与帖子保存成功才显示发布成功；失败新增资源有回收机制。
- [ ] R1：响应丢失后同次提交重试只生成一帖；并发点击或重复请求不生成重复帖子。
- [ ] R1/R9：返回、重新进入、登录取消和断网不主动清空草稿；图片路径失效提示重选；成功后清草稿，用户可确认丢弃草稿。
- [ ] R2：详情可同时看到品牌、价格、期待效果和试穿照片，品牌不与渠道混淆。
- [ ] R1/R10：发布成功立即进入真实社区，说明反馈查看入口；微信分享是可选辅助动作，不设邀请好友才能曝光或发帖的门槛。

## 期限与决策

- [ ] R6：退货状态必须明确选择，未知、不能退、知道截止日期三种输入不混用，不默认三天。
- [ ] R6：北京时间截止前一天、当天、次日显示正确；页面重新显示和持续跨日后更新，客户端其他时区不改变结果。
- [ ] R6：服务端时间用于期限判断；客户端请求失败不显示虚假实时期限。
- [ ] R6：过期不自动变为留下；作者能修正日期，修改不改变已有意见、票数与创建时间，非作者修改被拒绝。
- [ ] R6：0–3 天快到期排序正确，同日最新优先；已拍板、已结束投票、过期、未知和不能退不混入。
- [ ] R6：说明商家实际截止时间为准、应提前操作；没有订阅消息、短信或保证防止错过期限的误导文案。
- [ ] R7：每账号每帖一票，可改投；重复/并发请求不增加重复票；作者投自己、投票已结束或已拍板后投票由服务端阻止。
- [ ] R7：零票有空状态，少于 5 票有小样本提示；没有“必须 8 票”门槛或把多数票直接当最终决定。
- [ ] R7：只写搭配意见不产生留退票；意见 4–180 字、署名来自账号；作者补充准确标记；只能撤回自己的意见，撤回时其下回复一并隐藏且计数正确。
- [ ] R7：任意登录用户可回复意见形成多层级讨论；回复不产生或改变留退票，投票结束后仍可回复；越权删改他人意见被拒绝。
- [ ] R8：作者可在任何阶段单独「结束投票」，也可直接记录留/退结论；两种状态可并存，互不覆盖，过期不使该动作失效。
- [ ] R8：结束投票后票数保留并标注已结束，不显示留/退结论；帖子退出待帮看与快到期。
- [ ] R8：零票也能收束，理由选填且长度校验；所有页面同步状态；明确不会代办退货退款。
- [ ] R8：只有作者可结束投票或修改结论；修改不重开投票；结束投票或拍板后仍可补充评论与回复。

## 分享与身份

- [ ] R3：真实微信卡片包含稳定帖子路径与首图、合适标题，不带令牌或个人账户标识；分享面板打开不伪报已送达。
- [ ] R3/R9：朋友在另一台设备冷启动直达原帖，免登录浏览照片、背景、票数和意见，不先进入首页或登录页。
- [ ] R3：单帖读取不依赖完整列表；非法 ID、已删除和下架显示不可用，网络失败另有重试，不以示例冒充原帖。
- [ ] R9：登录后回原帖或原草稿，保留输入和投票意图；取消/失败不丢内容，恢复执行最多一次。
- [ ] R9/R10：从社区首页进入的陌生用户同样免登录浏览，首次参与后登录返回原帖，不依赖分享入口或好友关系。
- [ ] R9：登录途中帖子被拍板、结束投票或删除时不执行失效投票；过期会更新提示但不擅自拍板。
- [ ] R9：真实微信账号登录与合法 HTTPS 域名在真机可用；开发配置不误用于正式版，客户端不含服务端密钥。

## 社区与个人记录

- [ ] R2：品牌输入查找、点击查找、去空格、字母大小写、包含匹配、清空及空结果均符合规格。
- [ ] R10：社区默认待帮看，另有最新/快到期与品牌查找；不以已有票数、作者粉丝数或争议程度决定曝光。
- [ ] R10：待帮看只含真实可见、未拍板且投票未结束的留退帖；快到期优先、同截止日无反馈优先、同组先发布优先；其余无反馈优先且排序稳定，作者补充与回复不算他人反馈，一票不代表已解决。
- [ ] R10：最新可浏览已拍板与已结束投票的结果；品牌条件与视图组合正确；删除/下架/历史 style/演示帖不进入待帮看。
- [ ] R10：我的进行中、已结束投票、已拍板、我参与的归类正确；作者能看真实票数/意见数，参与者能回访最终决定和理由。
- [ ] R10：没有反馈时不要求作者拉朋友；空社区不制造虚假热度或承诺及时回复，首版不声称已主动推送反馈。
- [ ] R10：演示帖与真实社区隔离，明确标记，不能参与真实投票、品牌结果或验证指标。

## 个人行为统计

- [ ] R11：「我的」展示已发布帖子、已投票帖子、评论与回复三个指标，不宣传为终身累计、奖励积分或意见质量。
- [ ] R11：发布成功计 1，草稿/演示不计；已结束投票和已拍板仍计，删除/下架后不计。
- [ ] R11：每账号每帖一票计 1，改投/重复请求不增加；投票关闭后有效历史票仍计，删除/下架帖上的票不计。
- [ ] R11：顶层评论、作者补充、各层回复每条计 1，决定理由不计；撤回、移除、父评论撤回后隐藏的回复不计。
- [ ] R11：统计来自服务端会话账号的完整 Vectoree 有效记录，超出列表分页也正确；不信任客户端提交身份或本地点击累计。
- [ ] R11：写入失败不加，刷新与换设备结果一致；退出登录和切换账号不泄露旧统计，未登录有提示，加载失败显示重试而非假零。
- [ ] R11：已发布/已投票能定位个人记录；评论与回复仅汇总，不为此增加消息中心、独立评论历史页或奖励接口。

## 隐私与治理

- [ ] R4：发布前明确公开社区及分享不等于私密，提示可不露脸、不上传地址等敏感信息，并有主动公开确认。
- [ ] R4：作者可确认删除，他人越权删除失败；列表、我的、按 ID 读取及分享都不再展示原帖，关联图片无法绕过可见控制继续访问。
- [ ] R4：图片清理失败可重试，内容不会重新出现；无法立即撤销缓存/存储访问时不得宣称已彻底移除，作为上线前修复项。
- [ ] R5：帖子/意见举报可提交，待处理重复举报幂等；回复只是收到举报，不宣称已处理。
- [ ] R5：受限运营权限可实际处理举报并移除内容；普通账号不能读举报队列或治理内容；移除意见后计数正确。
- [ ] R5/R9：正式上线所需类目、审核、内容安全、隐私说明及适用账号注销能力经核查；未核查项目有明确阻塞记录。

## 兼容与完整验证

- [ ] 历史正文、图片和互动不丢失；缺少新字段可读取；旧剩余天数显示待确认，不从今天起人为续期。
- [ ] 历史 style 帖可浏览评论、不出现留退投票/拍板且不计入待拍板；旧 both 帖仍可正常使用留退流程；历史意见无回复关系时按单层正常展示。
- [ ] 旧网页请求与新共享契约兼容；真实期限语义不回退为固定不变的剩余天数。
- [ ] 现有行为回归、新增边界测试、静态检查和构建通过，失败项新增修复任务后复验；所有结果可重现。
- [ ] 两台真实设备完成至少一条非演示帖的发布、微信分享打开、他人反馈、作者结束投票或拍板、结束后评论互动与原帖结果回访。
- [ ] 至少一条非演示帖在作者未分享给朋友的情况下完成「发布→陌生人从社区发现→真实反馈→作者收束→参与者回访」；含作者只结束投票未给结论、以及结束后继续评论互动的用例；熟人分享测试不代替此项。
- [ ] 招募真实求助者和愿意帮看的消费者完成种子社区试用，允许角色互换；通过访谈确认陌生关系，不把不同账号或没点分享自动当作陌生人。
- [ ] 记录观察窗口、首条陌生人反馈时效、未响应帖子占比、意见帮助程度、是否更快决定与重复参与意愿，运营协助与自发参与分开；无反馈样本不被静默排除。
- [ ] 验证数据排除演示/测试数据，未知期限不计入期限前拍板率，分享入口点击不当作送达；社区供给不足有明确记录，不把排序规则当作已有反馈供给。
