- [x] 1. 核实并扩展共享数据契约（R1、R2、R6、R7、R8）。
  描述：读取当前框架指南与适用 Vectoree 技能，核实数据库字段、写入权限和部署状态；明确品牌、期待效果、期限状态/日期、决定理由、投票结束状态、意见回复关系、内容可见状态和提交幂等标识。为旧帖子/旧网页请求做兼容，不凭旧剩余天数生成新期限，不把购买渠道当品牌。
  验证：新旧数据均可读取；旧内容及互动保留；数据迁移可重复执行且不输出密钥。实际配置和表结构不符合假设时先更新规格，不擅自重建数据库。
  本地结果：共享类型、兼容映射与准备 SQL 已实现，服务端回归通过。实际 schema、权限与迁移重复执行验证留待任务 10。

- [x] 2. 补齐单帖、写入与状态服务（R1、R3、R6、R7、R8、R9）。
  描述：支持无需账号按 ID 读取可见帖子；服务端校验新增字段、图片和作者权限；实现发布重试幂等、唯一投票、意见回复（含多层级与归属校验）、作者修改期限和决定理由；把「结束投票」与「记录结论」做成两个独立且可并存的作者动作，投票关闭与结论记录互不覆盖。历史 style 帖仅浏览/评论，示例不接受真实互动。
  验证：重复发布/投票不重复计数；失败资源回收；越权操作失败；投票已结束（含仅结束未给结论）不能再投票或改投；过期不会自动拍板；未知与不能退可区分；回复不改变票数，非作者不能代结束投票或删改他人意见。
  本地结果：单帖与写入 API、回复树、关闭投票、日期修正及失败资源回收已通过 mock 回归；跨进程事务保护依赖待应用 SQL，实际验收留待任务 10。

- [ ] 3. 实现简化发布和本地草稿（R1、R2、R4、R9）。
  描述：新帖表单只保留照片、具体纠结、期待效果、品牌、价格和期限状态/日期；移除重复标题、示意图与独立类型选择。原有标题字段由纠结文本生成摘要；支持封面顺序、照片错误定位、本地草稿恢复和明确公开发布确认。
  验证：1–9 张图、价格小数和字段边界可用；返回/登录/断网不清空输入；失效临时图片有重选提示；成功才清草稿，重试不产生重复帖；发布后进入社区，不要求分享给朋友。

- [ ] 4. 实现可判断、可拍板的帖子详情（R2、R6、R7、R8）。
  描述：照片与问题优先，展示已填品牌、价格、期待效果和真实期限；简化意见署名，作者补充有标记；意见展示为可回复的多层级讨论，作者可参与互动；展示真实票数、小样本提示与「投票已结束」状态，零票也能记录决定，可选理由；作者可随时单独结束投票，也可直接记录结论，两者都不重开投票。失败显示重试，不伪造不存在。
  验证：作者和他人看到正确动作；评论与回复不自动投票；意见可撤回并正确隐藏其下回复；投票结束后仍可评论但不能再投票；作者能区分「已结束投票未给结论」与「已留/已退」；历史 style 帖不出现留退控件；明确拍板不代为退款。

- [ ] 5. 打通社区登录恢复与辅助微信分享（R3、R9）。
  描述：从社区或分享进来的用户都可免登录浏览，写入时微信登录并恢复原帖/草稿与待执行意图；恢复后再检查状态，避免重复操作。详情保留原生朋友/群分享，使用帖子 ID 和首图，冷启动按 ID 直达；分享不作为获得社区曝光的门槛。小程序区分开发与正式 API 配置，敏感密钥留在服务端。
  验证：真实账号、合法 HTTPS 域名下完成社区进入后的首次登录投票和取消登录，另用两台设备验证分享打开；删除/已拍板后的回跳不会执行过时意图。无法获得真机或微信条件时保持未完成。

- [ ] 6. 建立陌生人社区的发现与回访闭环（R2、R6、R10）。

  验证：作者未分享到朋友，其他无好友关系用户仍可从社区发现该帖并反馈；待帮看排序稳定、已结束投票与已拍板不混入、作者补充与回复不算他人反馈、一票不移除待帮看；品牌与视图组合、清空、空结果一致；快到期范围正确；作者能查看反馈，参与者能回访结果。

## 依赖与执行规则

1. 任务 1 是后续数据实施的前置，任务 2 依赖任务 1。
2. 任务 3、4、5、6、7 在任务 2 的接口与状态契约明确后可并行；共享文件必须分配单一负责人，避免并行覆盖。
3. 任务 6.1 依赖任务 2 的数据与身份契约，和任务 6 约定「我的」文件负责人，避免覆盖。任务 8 依赖任务 3–7（含 6.1）；任务 9 的账号与审核条件可提前核实，完整试用依赖任务 8。
   社区发现与反馈回访是主流程；不能只完成分享链路就声称 MVP 闭环。真实参与者招募是验证前置，不由技术排序替代。
4. 批准后使用专门子代理实施，使用独立子代理验收，并同步 update_plan 与本文件状态。
5. 如需修改公开范围、引入站外提醒、重新设计品牌或增加 AI，先形成单独增量规格，不混入本 MVP。
